# 路线图

路线图只记录已经决定的下一步，不把愿望清单当作承诺。当前优先级是把静态站点和内容基础做稳。

## 当前：静态首版

- Astro 单根项目可安装、开发、构建和预览。
- 首页及 `Studio`、`Journal`、`About` 导航可用，并在窄屏下保持可读。
- Studio、Journal、固定页面使用 schema 校验的仓库内容。
- lint、格式检查、类型检查、测试、构建和 Playwright 冒烟形成 CI 质量门。
- 许可证明确区分代码与内容/品牌资产。

## 下一步：内容与细节

1. 补齐一组真实的 Studio 项目和 Journal 文章，验证关联、草稿和排序规则。
2. 用真实内容检查首页、列表、详情和 About 的阅读节奏、SEO 元数据与分享卡片。
3. 根据真实设备检查键盘、对比度、减少动效和图片加载表现。
4. 保持 `pnpm check` 和 Playwright 冒烟稳定，减少每次发布前的手工判断。

## 决策门

- **需要远程内容编辑？** 先评估静态内容工作流和最小 CMS 边界，再单独立项；不在首版中预埋 CMS SDK。
- **需要表单或数据交互？** 先确认隐私、存储和 API 责任，再决定是否新增后端；静态站点本身不伪装成服务端应用。
- **需要线上发布？** 先确定域名、托管、缓存、回滚和品牌资产授权，再建立 deployment workflow；当前 CI 不部署。

在这些决定完成前，明确非目标仍是后端、数据库、登录、动态插件、队列、后台管理和企业业务流。
